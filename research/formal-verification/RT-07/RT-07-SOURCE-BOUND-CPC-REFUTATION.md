# RT-07 — Bind a checked CPC refutation to typed source

**Date** · 2026-11-21

**Baseline** · `11c7f19`

**Status** · Direct-path SCW-33 experiment for [Plan §2.3](../../PLAN.md#23-lean-logos-smt-and-solver-integration)

## Question and comparison

Can a checker distinguish a valid refutation of the source-derived relational query from a valid refutation of a different query? An externally supplied expected query can make the proof and expectation agree even when they misrepresent the source. A direct source gate reconstructs the expected formula from typed source and compares the complete parsed assumptions before invoking Logos. It requires the typed input, declaration context, factor and observation contract. A versioned wire path could relay the same information across components, but needs its own correspondence evidence. [Scenario 34 proof boundary](RESEARCH-SCENARIO-34-SOURCE-TO-QUERY-SEMANTIC-CORRESPONDENCE.md#76-qf_lia-admissibility-and-external-wirechecker-boundary)

The direct gate uses the already proved declaration-closed QF_LIA lowering. It binds the exact declarations by name and sort in the retained CPC parser state, decomposes the source formula into the factor difference and the observation difference, and structurally checks both assumptions in order. It passes the parsed assumption and command pair to Logos and accepts only the complete `correct` verdict. This path does not consume JSON or rely on an expected expression supplied with the proof.

## Controls

| Control | Observation |
|---|---|
| Constant program returning 7 | A CPC derivation generated by cvc5 1.4.2, with four fixed aliases expanded in the fixture, passes source binding and the Logos verdict. |
| Refutation with the observation assumption replaced by false | The standalone Logos checker reports `correct`. The source gate rejects the substituted assumption. |
| Reuse the constant-program derivation for a program returning the input | Declaration names and sorts still agree. Source assumptions differ, so the direct gate rejects it. |
| Matching assumptions without proof commands | The binding stage succeeds. The verdict stage rejects the missing refutation. |
| Reorder assumptions or name an undeclared factor | The source gate rejects both. |
| Keep the solver-emitted aliases | Standalone Logos reports `correct`. The existing strict source declaration binder rejects the extra aliases retained in parser state. |

The last case delimits interoperability with real solver output. The fixture expands only its four known nullary terms in test data. It does not add a CPC macro rewriter or permit aliases in the checker. A broader profile needs a precise distinction between declared constants and admitted proof-local definitions, including equality of the resulting assumptions.

This study establishes an executable check over parsed terms for the tested fragment. It does not prove universal denotation preservation through the final renderer or parser state, establish a new Logos soundness theorem, generalize the alias policy, or close the JSON path. The experiment uses the ordinary Lean executable and the pinned Logos implementation of `logos_verdict`. [Formal verification architecture](LLMLang-FORMAL-VERIFICATION.md)

## Reproduction

Use Lean 4.36.0 and the repository's pinned Logos revision. From `research/PROTOTYPES/DEPENDENCY-GRAPH-01/logos_binding` run the build and both test drivers. The new source-bound controls and existing parser-state tests passed.

```sh
lake build --fail-fast LLMLangLogosBinding
lake env lean -DwarningAsError=true --run SourceCpcRefutationTests.lean
lake env lean -DwarningAsError=true --run Main.lean
```
