# Executed RV64 HAL comparison under local Sv39 remap and revoke

[GitHub #441](https://github.com/aivibeflow/LLMLang/issues/441) · 2026-11-25

This experiment links the previously checked assembly and LLVM HAL leaves into the same freestanding Sv39 remap fixture. The guest boots on QEMU 10.0.13 `virt`, RV64, one hart, 64 MiB of RAM and no firmware image. The setup first compares the returned stack pointer with the active machine stack pointer. Trap handling uses separate HAL calls for data ordering and local translation maintenance after changing or clearing the page-table entry.

The source-level observation requires the user compartment to read frame A before the remap, read frame B afterward, then report a page fault and recover after revocation. The runner checks the exact final ELF and UART trace.

| HAL image | Observed result |
| --- | --- |
| Handwritten assembly | `HBEISRAMBDPZ!` |
| LLVM IR through O0, O2 and O3 | `HBEISRAMBDPZ!` in each image |
| Stack-pointer control adds 16 | `X` from the early HAL check |
| Translation control substitutes a second data fence | `HBEISRAMADA!`, with the stale frame A observed after each update |

The emitted stack-register intrinsic and sequentially consistent data fence match the corresponding assembly words. LLVM's explicit side-effecting target assembly provides the translation instruction. All six ELF images have identical user-compartment bytes. The linked-word audit checks each HAL leaf, the machine load regions, lack of undefined symbols, absence of relocations and absence of a dynamic loader. The two controls preserve link closure and fail distinct observation gates.

This result checks execution through real guest privilege and translation transitions under the stated QEMU profile. It leaves physical-hart ordering, selective address and ASID scope, remote shootdown, DMA, whole-program lowering and linker proof beyond this fixture open. ## Replay

Use CPython 3.12.14, Debian LLVM/LLD 19.1.7 and `qemu-system-riscv64` 10.0.13. The runner reuses the repository's exact Sv39 boot and HAL sources and records the QEMU binary digest. Pass `--qemu-data` when the package's shared machine data lives outside the default path.

```sh
fixture=research/runtime-and-systems/RT-38/RV64-HAL-QEMU-01
python -B "$fixture/run.py" --qemu /path/to/qemu-system-riscv64 \
  --output /tmp/rt38-hal-qemu.json
cmp "$fixture/evidence.json" /tmp/rt38-hal-qemu.json
```
