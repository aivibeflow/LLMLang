# 0002 — Echo

**Task ID:** `0002`  
**Difficulty:** 2 — basic  
**Status:** Proposed  
**Prerequisites:** 0001 — Hello, World!  
**Related tasks:** 0003

## 1. Purpose

Exercise command-line argument access, iteration, string handling, and deterministic output formatting.

## 2. Problem Statement

Write a command-line program that writes its command-line arguments to standard output, joined by one ASCII space, followed by one LF.

The program must not print its own executable name.

For example:

```console
$ echo-args alpha beta "two words"
alpha beta two words
```

With no arguments, it prints an empty line.

## 3. Behavior and Interface

### Inputs

- The program receives zero or more command-line arguments.
- Arguments are treated as opaque strings supplied by the runtime. The program must preserve each argument's contents; it must not split an argument on whitespace.
- The executable name / argument at index zero is excluded.

### Outputs

- Write each argument, in original order, to standard output.
- Write exactly one ASCII space (`0x20`) between adjacent arguments.
- Write exactly one LF (`0x0A`) after the final argument.
- With zero arguments, write only LF.
- Write nothing to standard error on success.
- Exit with status code `0` on success.

### Errors and Edge Cases

If writing to standard output fails, terminate unsuccessfully. The exact nonzero exit code is implementation-defined.

An argument may be empty. Empty arguments must still occupy their position in the sequence. Thus two empty arguments produce one separating space and the final LF.

## 4. Requirements

- **R-0002-01:** The program excludes the executable name from the output.
- **R-0002-02:** The program preserves the order and contents of all supplied arguments.
- **R-0002-03:** Adjacent arguments are separated by exactly one ASCII space, with no leading or trailing separator other than the final LF.
- **R-0002-04:** The program writes exactly one LF after all arguments; with no arguments, it writes only LF.
- **R-0002-05:** On success, standard error is empty and the process exits with status code `0`.
- **R-0002-06:** If output fails, the process exits with a nonzero status.
- **R-0002-07:** Argument boundaries are preserved; whitespace inside an argument is not treated as a separator.

## 5. Constraints and Non-Goals

### Constraints

- Use the LLMLang standard library for argument access and standard output.
- No third-party dependencies.
- Output formatting is deterministic.
- The task does not require shell parsing: the operating system/runtime has already supplied the argument vector.

### Non-Goals

- No option parsing or flag interpretation.
- No quoting or escaping of arguments.
- No environment-variable processing.
- No configurable separator or terminator.
- No guarantee for arguments that the host process interface cannot represent.

## 6. Acceptance Criteria

- [ ] Every argument except argv[0] appears exactly once and in the original order. (R-0002-01, R-0002-02)
- [ ] The output uses exactly one separator between argument positions and preserves embedded whitespace. (R-0002-03, R-0002-07)
- [ ] Output always ends with exactly one LF; zero arguments produce one LF. (R-0002-04)
- [ ] Successful execution leaves stderr empty and exits 0. (R-0002-05)
- [ ] An output failure results in a nonzero exit status. (R-0002-06)

## 8. Concepts Exercised

- Runtime-provided argument vector
- Sequence iteration
- String/byte handling
- Conditional separator emission
- Standard output and error propagation
- Empty values and boundary cases

## 9. Completion Definition

A completed solution contains a LLMLang source implementation and tests for all scenarios above. Record parser/build/runtime status. If the language toolchain cannot yet execute the source, mark it as illustrative and unverified.

## 10. Implementation Notes

A robust implementation can emit the separator before every argument except the first. Avoid concatenating the entire output in memory unless the language's string model makes that preferable.
